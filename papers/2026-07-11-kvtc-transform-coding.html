KV Cache Transform Coding (kvtc)
— Treat the KV cache like a JPEG: decorrelate, quantize, entropy-code for 20× compact storage— KV 캐시를 JPEG처럼: 탈상관 → 양자화 → 엔트로피 코딩으로 20× 압축 저장

👥 Konrad Staniszewski & Adrian Łańcucki, Adrian Łańcucki (2인) 🏛 NVIDIA · University of Warsaw 🗓 2025.11.03 📄 arXiv:2511.01815
⚡ TL;DR

Chat and code-editing reuse the same KV cache across turns, but stale caches eat GPU memory — you either offload them (transfer cost) or recompute them (an O(N²) prefill). kvtc borrows the classical media-compression recipe (as in JPEG): decorrelate features with a PCA basis learned once on calibration data and reused for every cache, allocate bits across principal components with an optimal dynamic-programming quantizer, then losslessly entropy-code with GPU DEFLATE. Unlike xKV/SVDq it needs no per-prompt SVD and leaves model weights untouched. Result: ~20× average compression within <1 point of the uncompressed model (up to 40×+ at modest cost), and because decompression beats recomputation it cuts time-to-first-token up to 8× on an 8K context.

채팅·코드 편집은 턴마다 같은 KV 캐시를 재사용하지만, 남은 캐시는 GPU 메모리를 잡아먹는다 — 오프로드하면 전송 비용, 버리면 O(N²) prefill 재계산이다. kvtc는 고전 미디어 압축 레시피(JPEG처럼)를 빌린다: 캘리브레이션 데이터에서 한 번 학습해 모든 캐시에 재사용하는 PCA 기저로 특징을 탈상관하고, 최적 동적 계획법 양자화기로 주성분에 비트를 배분한 뒤, GPU DEFLATE로 무손실 엔트로피 코딩한다. xKV/SVDq와 달리 프롬프트별 SVD가 불필요하고 모델 가중치도 건드리지 않는다. 결과: 무압축 대비 <1점 이내에서 평균 약 20× 압축(적은 손실 감수 시 40×+), 재계산보다 빠른 복원 덕에 8K 컨텍스트에서 첫 토큰까지 시간(TTFT)을 최대 8× 단축.

Why it matters왜 중요한가

Most KV-cache work optimizes the decode loop; kvtc optimizes the shelf the cache sits on when nobody is decoding.

대부분의 KV 캐시 연구는 디코드 루프를 최적화한다; kvtc는 아무도 디코딩하지 않을 때 캐시가 놓인 '선반'을 최적화한다.

Serving systems treat KV caches as databases — block paging and prefix sharing reuse them across turns. But a Llama 3.1 8B cache costs 128 MiB per 1K tokens, so retained caches quickly overwhelm GPU HBM. The choices are all bad: keep it on-chip (blocks other users), offload to DRAM/network (transfer overhead), or discard and recompute (quadratic prefill). Runtime compressors — quantization (KIVI, GEAR), token eviction (H2O, TOVA) — are tuned for the tight-latency decode path, so they are brittle and don't combine well. kvtc instead asks a different question: how small can you make a cache for storage, where you can afford a one-time transform? By exploiting the strong low-rank structure and cross-head correlation of KV tensors, it hits far higher ratios than runtime methods while preserving accuracy — and it is complementary to them.

서빙 시스템은 KV 캐시를 데이터베이스처럼 다룬다 — 블록 페이징·프리픽스 공유로 턴 간 재사용한다. 그러나 Llama 3.1 8B 캐시는 1K 토큰당 128 MiB라, 남겨둔 캐시가 GPU HBM을 금세 가득 채운다. 선택지는 모두 나쁘다: 온칩 유지(다른 사용자 차단), DRAM/네트워크 오프로드(전송 오버헤드), 폐기 후 재계산(2차 prefill). 런타임 압축기 — 양자화(KIVI, GEAR), 토큰 퇴출(H2O, TOVA) — 는 빡빡한 디코드 지연에 맞춰져 있어 취약하고 서로 잘 조합되지 않는다. kvtc는 다른 질문을 던진다: 일회성 변환을 감당할 수 있는 저장용 캐시는 얼마나 작아질 수 있는가? KV 텐서의 강한 저랭크 구조와 헤드 간 상관을 활용해, 런타임 기법보다 훨씬 높은 압축비를 정확도 손실 없이 달성하며, 그것들과 상보적이다.

The three ideas that make it work작동을 만드는 세 아이디어

① 재사용 기저

A calibrated PCA basis, not per-prompt SVD

Prior low-rank methods (SVDq, xKV) run an SVD for every prompt — too slow to reuse across turns. kvtc computes one orthonormal basis V on a small calibration set and applies it to all caches. Two tricks make the low-rank structure clean: strip RoPE before projecting (positional rotation hides the low rank of keys), and exclude the first 4 "sink" tokens and a 128-token sliding window from compression.

기존 저랭크 기법(SVDq, xKV)은 프롬프트마다 SVD를 돌려 턴 간 재사용이 불가능할 만큼 느리다. kvtc는 작은 캘리브레이션 집합에서 직교 기저 V 하나를 계산해 모든 캐시에 적용한다. 저랭크 구조를 깔끔히 드러내는 두 트릭: 투영 전 RoPE 제거(위치 회전이 키의 저랭크성을 가린다), 그리고 첫 4개 "싱크" 토큰과 128 토큰 슬라이딩 윈도우를 압축에서 제외.

② 최적 비트 배분

Dynamic-programming quantization

PCA orders components by variance, so higher-variance components deserve more bits. A DP algorithm minimizes Frobenius reconstruction error under a global bit budget — and because V is orthonormal, the optimum can be solved directly in the decorrelated domain. It groups components (microscaling-style, sizes 1/16/64/256/1024) and, crucially, assigns zero bits to trailing components, which prunes both the payload and V itself.

PCA는 성분을 분산 순으로 정렬하므로 고분산 성분에 더 많은 비트를 준다. DP 알고리즘이 전역 비트 예산 하에서 Frobenius 재구성 오차를 최소화한다 — V가 직교이므로 최적해를 탈상관 영역에서 바로 구할 수 있다. 성분을 그룹화하고(마이크로스케일링 방식, 크기 1/16/64/256/1024), 결정적으로 후미 성분에 0비트를 배정해 페이로드와 V 자체를 함께 가지친다.

③ 무손실 마무리

GPU entropy coding

Quantized values are packed and compressed with DEFLATE, run in parallel on-GPU via NVIDIA's nvCOMP. This step is lossless and content-dependent, adding ~1.23× on average on top of quantization. The whole pipeline mirrors JPEG (DCT→quantize→Huffman); kvtc just swaps the DCT for a learned PCA and Huffman for DEFLATE.

양자화 값을 패킹해 DEFLATE로 압축하며, NVIDIA nvCOMP로 GPU에서 병렬 실행한다. 이 단계는 무손실·내용 의존적이며 양자화 위에 평균 ~1.23×를 더한다. 전체 파이프라인은 JPEG(DCT→양자화→허프만)를 그대로 닮았고, kvtc는 DCT를 학습된 PCA로, 허프만을 DEFLATE로 바꿨을 뿐이다.

What to take away그래서, 가져갈 것

🗄

Storage is a distinct problem from decode. By relaxing the tight-latency constraint of runtime compression, kvtc can afford a real transform and reaches far higher ratios — and it composes with eviction/quantization rather than competing.

저장은 디코드와 별개의 문제. 런타임 압축의 빡빡한 지연 제약을 풀어주면 kvtc는 제대로 된 변환을 감당해 훨씬 높은 압축비에 도달한다 — 퇴출·양자화와 경쟁이 아니라 조합된다.

📼

Classical codec wisdom transfers. Decorrelate → quantize → entropy-code is 30 years of JPEG/MPEG engineering; KV tensors turn out to be a natural fit for it, which is a fertile analogy to keep mining.

고전 코덱의 지혜가 이식된다. 탈상관 → 양자화 → 엔트로피 코딩은 JPEG/MPEG 30년의 공학이다; KV 텐서가 여기에 잘 맞는다는 것은 계속 파낼 만한 비옥한 유비다.

♻️

One reusable basis beats per-prompt SVD. Calibrate once, no weight changes, PCA overhead ~2.4% of a 70B model's params — cheap enough to be a default building block in a serving stack.

재사용 기저 하나가 프롬프트별 SVD를 이긴다. 1회 캘리브레이션, 가중치 무변경, PCA 오버헤드는 70B 파라미터의 ~2.4% — 서빙 스택의 기본 구성요소로 삼을 만큼 저렴하다.

⚠️ One critical note: the "20×" headline blends a lossy quantization target (16×) with a data-dependent DEFLATE gain (~1.23× on average), so the realized ratio is content-dependent and not guaranteed — the reported 60–88× spread on a single model makes that clear. Long-context accuracy does erode at aggressive settings (LITM 90.2, Qasper 37.8 at 64×), and most downstream evals use a single seed with greedy decoding (only Qwen runs are averaged with std). kvtc also only pays off in reuse scenarios: for one-shot prompts the compress/decompress cost (hundreds of ms at 8K) is pure overhead. ⚠️ 한 줄 비판: "20×" 헤드라인은 손실 양자화 목표(16×)와 데이터 의존적 DEFLATE 이득(평균 ~1.23×)을 합친 값이라, 실현 압축비는 내용에 좌우되며 보장되지 않는다 — 단일 모델에서 60–88×로 벌어지는 범위가 이를 방증한다. 공격적 설정에선 장문 정확도가 실제로 하락하고(64×에서 LITM 90.2, Qasper 37.8), 대부분의 다운스트림 평가는 단일 시드·그리디 디코딩이다(Qwen만 표준편차와 함께 평균). 또 kvtc는 재사용 시나리오에서만 이득이다: 일회성 프롬프트에선 압축/복원 비용(8K에서 수백 ms)이 순수 오버헤드다.
